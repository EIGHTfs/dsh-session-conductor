# 任务完成汇报（task-completion-report）

> 本 skill 内容经 systemPrompt.section「task-completion-report」注入每个 agent（order 1000）。

## 一、规则

**每次完成有交付物或实质结论的任务，回复结尾必须：**

1. **一整行 ═ 分隔线**（`══════════════════════════`，20 个 ═）
2. **醒目状态标记**（分隔线下第一行）：
   - `✅ 任务完成`（成功）
   - `❌ 失败`（失败，附原因）
   - `⚠️ 未完成`（部分完成，附缺口）
3. **三要素**（状态标记后）：
   - **交付了什么**：文件路径 / 功能 / 结论
   - **验证状态**：如实区分「实测通过 / 单测通过 / 待人工确认」，禁止虚报
   - **遗留事项**：已知边界 / 待办 / 坑

**简化规则**：纯咨询或闲聊可简化为一行「✅ 已解答」。

## 二、格式示例

```
══════════════════════════
✅ 任务完成

交付：
- <文件路径 / 功能 / 结论>

验证：
<实测通过 / 单测通过 / 待人工确认 + 具体证据>

遗留：
<已知边界 / 待办 / 坑>
══════════════════════════
```

## 三、配套工具

- `task_completion_render`：渲染标准收尾块（分隔线 + 状态标记 + 三要素），任务结束前调用，把返回文本原样贴到回复结尾。
- `task_completion_check`：校验一段文本是否符合收尾格式（分隔线/完成标记/交付/验证/遗留），写完成汇报后自检用。
