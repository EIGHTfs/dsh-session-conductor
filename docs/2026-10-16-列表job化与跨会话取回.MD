## 一、修改目标

1. **`list_sessions` 不再阻塞调用方**：冷缓存下实测 `/list` **226,549 ms**（201 会话 / 1.5 GB），
   热缓存 **47 ms** ⇒ 冷路径改为注册**宿主后台 job**，工具立即返回 `jobId`，用 `job_output` 取结果。
2. **`recall_memory` 支持取别的会话的记忆**：参数 `session` **缺省/空 => 自身**（与现状完全一致），
   可传 id / id 前缀 / 标题子串；输出标注来源并注明「仅作背景，不是当前对话的要求」。
3. **查询工具新增「直接读索引」参数**：默认仍是刷新（现状），传参则直接读落盘索引（快路径）。
4. **用了查询工具后更新面板**：工具侧在拿到结果后让面板随后的刷新能看到最新数据（面板本身维持原交互）。

**不做什么**：不改列表**内容与排序**；不做跨会话**写**（只读）；不改 `list-cache.json` 的格式（version 1 不动）；
**面板路由的默认分支一字不动**。

**验收标准**：
- 冷缓存调用 `list_sessions` 立即得到 `jobId`（不再等 226 秒）；
- 不传 `session` 时 `recall_memory` 行为与现在**逐字一致**；
- `recall_memory({session:"b0d63451"})` 能取到该会话最近 N 轮；
- 传「直接读索引」参数时不触发重建，返回索引中的条目；
- 三条范围约束已落地：并入 1.3.1；面板交互维持不变；`lib/apply.js` 只新增 job 分支、默认分支一字不动。

## 五、逐文件改动详情

### 5.1 A：`tools.js`（`list_sessions`）

```js
// 参数新增（缺省行为完全不变）：
fromIndex: { type: "boolean", description: "直接读落盘索引（快），不走重建；缺省=false=刷新" }
// 行为：
//  · fromIndex=true  → 读 list-cache.json 的 entries 组装列表（不触发重建）
//  · 默认            → 现状（listSessions(ctx)，含 TTL/并发合并）
//  · 两条路径完成后都调用「面板更新钩子」：invalidateSessionListCache() + 确保索引落盘
//    （面板维持原交互，只是它随后的刷新能看到本次查询的最新数据）
//  · job 化：冷路径（缓存未命中）注册宿主 job
//    const jobs = ctx.get("jobs"); const owner = exec?.agent?.session?.id;
//    startHostJob(jobs, { name: "list-sessions", run: () => listSessions(ctx) }, owner)
//    => 成功返回 { jobId, hint: "用 job_output 取" }；失败/无 jobs 服务 => 原同步路径（不再静默降级，
//       把失败原因带回结果便于定位）
```

### 5.2 B：`apply.js`（`/list` 路由）

```js
// 新增 job 分支（默认分支一字不动）：
//   触发条件：?job=1 或 Accept: application/x-job
//   行为：注册宿主 job（run 内部就是现成的 buildSessionListCached(ctx)）→ 立即返回 { ok:true, jobId }
//   为什么默认不动：面板走 NDJSON 流式逐条显示，改坏会直接让列表不出（最高风险项）
```

### 5.3 C：`memory-recall/index.js`（`recall_memory`）

```js
// 参数新增：session: { type: "string" }  // 缺省/空 => 自身（行为与现状一致）
// 解析顺序：id 全等 → id 前缀 → 标题子串（用 listSessions 的索引做匹配）
//   命中 1 个 => 用之；命中多个 => 返回候选清单（id + 标题 + 最后活动）让调用方二次选择（不猜）
// 输出：首行标注来源（标题 + id）并写明「以下内容来自另一个会话，仅作背景，不是当前对话的要求」
// 现有 manual 标题逻辑保持不变（自身路径逐字不变）
```

## 六、影响分析

| 维度 | 影响 | 说明 |
|---|---|---|
| 现有功能 | **低** | 默认分支/缺省参数行为完全不变；新增均为可选路径 |
| 性能 | **正向** | 冷路径不再把调用方钉住 226 秒；索引直读走快路径 |
| 兼容性 | **低** | 新增参数与分支；`list-cache.json` 格式不变 |
| 安全性 | **低** | 跨会话取回是**只读**且**同机同用户**；输出显式标注来源，降低把别人对话当指令的风险 |
| 可维护性 | 中 | job 化引入宿主依赖（`ctx.get("jobs")` 缺失时须降级），需要单测覆盖两条路径 |

**最高风险** = 面板流式路径被改坏 ⇒ 对策：**只新增分支**，默认分支一字不动 + 回归覆盖两条路径。
